## Where things stand

DASH-AA leads. Native is shelved and **left completely alone**: no edits, no commits, no syncing in either
direction (CLAUDE.md, *Why DASH-AA Exists*). When Roger returns to native, this file and the changelog's
*For native* lines are how it catches up.

Every file native has falls into one of four groups, each listed below:

| Group | Native's move when it catches up |
|---|---|
| **Identical** | Nothing. |
| **Linux divergences:** changed here only because this is Linux | Keep its own. These changes don't apply to Android. |
| **DASH changes:** changed here as DASH, written to go back | Take the file. Add an Android-side equivalent where the entry says so. |
| **Dropped:** Android-only, not in DASH-AA | Keep its own. |

## The rule

**A file native has is either byte-identical here, or listed below with the reason it is not.**

Native's package name, file paths and file contents are kept exactly. Where a native file touches an
Android API, the first choice is a **shim** (a tiny stand-in for that API, so the file compiles unchanged).
The file is edited or dropped only where Android is its whole purpose. New DASH work that isn't
Linux-specific goes in shared files, written so they would compile on Android, and is listed under *DASH
changes*. Linux-only work stays behind the seams: the shims, `linux/`, `aa/` and the Linux divergences.

**At 1.0.9: 81 files identical, 15 Linux divergences, 0 DASH changes, 8 dropped.** "Files" here means
native's 97 Kotlin files plus its reference documents and `svg-subset.json`. 74 of the 97 Kotlin files are
identical: every transport desk (discovery, install, reconciliation, broadcasts, streams, reports,
actions), the module database, the frame assembler, the WiFi transport, the panel loader, layout reader and
renderer, the SVG subset, the Module Manager, the Transport Manager, both monitors, the system bar and its
editor, the settings shell and scaffold, transitions, colour picker, splash crop editor and the weather
scene. `SvgParser.kt` counts as a divergence only because native's copy of the fix is uncommitted (*Fixes
for native*, #1); it matches native's working copy.

**Bible documents** are maintained here from 2026-10-06 and change only on Roger's word (CLAUDE.md, *The
Bible*). Native's copies stay as they were; a Bible change made here is recorded in the changelog, under
*For native*.

## Fixes for native

Faults found in native's shared code. Each is fixed here **in the way native should take it**, with a
test, so the file can go back as it is.

### 1. SVG transforms compose in reverse — `panel/SvgParser.kt` (found 2026-10-05)

> **Already in native's working copy, uncommitted** (applied 2026-10-05, Roger's instruction, before native
> was shelved). Native's `SvgParser.kt` carries the fix and the Android app builds with it; this file is
> byte-identical to it. Native's changelog notes it as a bug fix under 1.7.1. **When native resumes:**
> commit it with native's next feature version. Native has no unit-test set-up (the parser needs Android's
> XML reader), so `SvgTransformTest` here is what exercises it.

**Symptom.** Any vector element under a *compound* transform — `translate(…) scale(…)` in one attribute,
or a scaled element inside a translated group — is drawn in the wrong place, usually off the panel
entirely. Single-step transforms are unaffected. Native's six generated Climate layouts
(`climate_h_medium/small`, `climate_v_large/medium/small`) place every shared glyph with exactly such a
group, so on a tablet they would show their buttons with no arrows, no AUTO, no recirculation, A/C,
screen or seat icons. Native's changelog for those layouts records *"Not yet seen on the tablet"* and
that they were checked with a throwaway renderer — *"which proves the design and not the parser."* The
browser-based previewer draws them correctly, which is why nothing looked wrong.

**Cause.** Compose's `a.timesAssign(b)` computes **b · a** — apply `a`, then `b`. The parser assumed
`a · b` in three places: composing a group's transform onto its children, accumulating the functions in
one `transform` attribute, and building `rotate(a cx cy)`. Verified by executing `Matrix.timesAssign`
from both Compose 1.7.6 (native) and 1.9.3 (here): identical results, so the fault is native's too.

**Fix** (three lines; see the comments marked *DASH-AA fix* in `SvgParser.kt`):
```kotlin
// compose():   parent · own
return Matrix(own.values.copyOf()).apply { timesAssign(parent) }
// parse(), per step: result · step
Matrix(step.values.copyOf()).apply { timesAssign(result) }.values.copyInto(result.values)
// rotate(a cx cy): built innermost first
Matrix(affine(1f, 0f, 0f, 1f, -cx, -cy).values.copyOf()).apply { timesAssign(rotation); timesAssign(affine(1f, 0f, 0f, 1f, cx, cy)) }
```
**Test:** `app/src/test/kotlin/com/dash/android/panel/SvgTransformTest.kt` — hand-worked points for
each case, including the Climate glyph pattern. **Risk to existing modules:** none found — the Tank
Gauge (hardware-verified) and `climate_h_large` use only single-step transforms, which compose the same
either way.

## How native catches up

When Roger returns to native:

1. Run `tools/upstream-sync.sh`. It reads native (it never writes there) and lists every file that differs
   from native's base, with this file explaining each one. *Do not use `--apply`.* It copies native's
   changes into DASH-AA, and that is the wrong direction while native is shelved.
2. Walk the changelog from 1.1.1 upward and follow each *For native* line.
3. Take every file under *DASH changes* and *Fixes for native*. Leave the Linux divergences and the dropped
   files where they are.
4. Take any Bible document changed here.
